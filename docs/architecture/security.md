# Security architecture

This application accepts text **and files** from anonymous visitors and shows them to other
visitors. That is the whole threat model in one sentence, and it is why security gets its own
document rather than a bullet in the style guide.

There are no user accounts ([CON-001](../requirements/constraints.md)). Moderation gates quality; it
does not gate abuse, and it happens after the upload has already been stored.

**Moved here 10 September.** These rules lived in `docs/ai/security.md` — the agent's instruction
directory — from 3 September, because the ADR directory did not exist yet when they were first
written. They are architecture, and their audience is anyone building or reviewing this system, not
only the assistant. What stayed behind in [docs/ai/security.md](../ai/security.md) is the part that
really is an instruction to the assistant. Two defects were found and fixed in the move; both are
named at the bottom.

Each section names the ADR that decided it. Where no ADR is named, the rule follows from a
requirement or a constraint directly.

## Uploads

The largest source of risk in the project. Storage location is decided in
[ADR-0006](adr/ADR-0006-media-storage-and-upload-security.md); the rules below are what makes that
storage safe. Every point is a requirement, not advice.

- **Type is decided by content, not by the client.** Apache Tika reads the magic bytes. The file
  extension and the `Content-Type` header are attacker-controlled and are used for nothing but
  display.
- **Magic bytes are necessary and not sufficient.** A **polyglot** carries a valid signature for an
  allowed type and is still a second type as well — a real `GIF89a` header followed by an HTML body
  is the standard example. OWASP is explicit that no single technique closes this, so the defences
  below are not belt-and-braces: they are the actual answer. Images are **re-encoded** rather than
  stored as uploaded, which destroys anything hiding behind a valid header.
- **Allowlist, never denylist.** Images, video, documents and audio — the four types
  [CON-006](../requirements/constraints.md) accepts. Executables, archives, SVG and HTML are
  rejected; SVG and HTML because they carry script.
- **The stored filename is generated by the system.** The original name lives in the metadata column
  and is never used to build a path. This is what closes path traversal.
- **Size limits** per file and per submission, enforced before the bytes are written to disk, at
  [NFR-001](../requirements/non-functional.md)'s configured values.
- **Delivery goes through a controller**, never by mapping a directory to a URL. The controller
  resolves the id to a stored file and checks that the resolved path is still inside the media root.
- **Response headers on delivery:** `X-Content-Type-Options: nosniff` always, and
  `Content-Disposition: attachment` for everything that is not an image the browser should render
  inline.
- **Video is streamed** with `Range` support, never loaded into memory.
- **Media stays unpublished until its submission is approved**, reachable only by an unguessable id
  and excluded from search (FR-016).

## Article content

Decided in [ADR-0001](adr/ADR-0001-article-body-format.md): the body is Markdown, and Markdown was
chosen over raw HTML precisely so that there is no HTML allowlist to hand-maintain.

- **Raw HTML passthrough is disabled in the Markdown converter.** This is the rule that makes
  ADR-0001 true rather than aspirational — a converter left in its permissive default would let a
  `<script>` block through untouched and reintroduce the surface the ADR was written to avoid.
- There is therefore **no HTML sanitizer** in this system. If one ever appears, it means raw HTML
  is being accepted somewhere, and ADR-0001 has been reversed without being amended.
- Templates escape by default; `th:utext` is allowed only for content the converter produced, and
  carries a comment saying so.
- Wiki links are resolved to internal routes; an external URL in article text is rendered with
  `rel="noopener noreferrer"`.
- The application never fetches a URL supplied by a visitor. That closes SSRF by not having the
  feature.

## Forms and abuse

Decided in [ADR-0008](adr/ADR-0008-abuse-handling-without-accounts.md).

- CSRF protection on every state-changing form.
- A CAPTCHA challenge on submission, not a honeypot — the reasoning, and the research that killed
  the honeypot, are in ADR-0008. The specific provider is still an open dependency decision.
- Rate limiting by IP on submission and on admin login, at
  [NFR-005](../requirements/non-functional.md)'s configured rate.
- A request body size limit at the container level, so an oversized upload is rejected before the
  application allocates for it.

## Reads

Decided in [ADR-0010](adr/ADR-0010-bounded-reads.md). Availability is part of the threat model, and
an unbounded read is the cheapest way to lose it.

- **The number of queries a page issues does not grow with the number of rows it shows.**
- **The fetch strategy is chosen, not discovered** — a join fetch, an entity graph or a batch size,
  decided when the query is written.
- **Every public list is paginated**, with a bound the client cannot raise.
- The gate that checks this — a query counter around the slice tests — arrives in phase 2 with the
  persistence layer.

## The admin area

Decided in [ADR-0009](adr/ADR-0009-admin-authentication.md).

- One shared password, taken from an environment variable, stored as a BCrypt hash. Never in
  `application.yml`, never in git.
- Failed login attempts are rate limited and logged at `WARN`.
- Session cookie: `HttpOnly`, `SameSite=Lax`, and `Secure` whenever the deployment is behind TLS.
- Every destructive admin action — delete, bulk import — is logged with what was affected. This log
  is the only trace of who did what, because the identity model deliberately has nobody to name.

## Data and secrets

- `.env` is git-ignored; `.env.example` carries names and shapes, never values.
- No secret in a log line, an exception message, or an error page.
- An export archive contains published content only ([ADR-0007](adr/ADR-0007-export-format.md)). It
  is a backup of the knowledge base, not a database dump, and it must be safe to email.

## Two defects found while moving this document

Both are exactly the failure the split was meant to stop: an architectural decision recorded in the
assistant's instruction directory, left behind when a later ADR or constraint superseded it, with no
check that would notice.

1. **The allowlist had lost audio.** It read "images, video and a small set of documents" while
   [CON-006](../requirements/constraints.md), written 7 September, accepts audio as well. The
   constraint is newer and is the product decision; the list above now matches it.
2. **It still required an HTML sanitizer.** It said to "sanitise HTML on the way in, and store the
   sanitised form" — written before [ADR-0001](adr/ADR-0001-article-body-format.md) chose Markdown
   on 6 September specifically so that no sanitizer would be needed. The rule above is now the one
   ADR-0001 actually implies: disable raw HTML in the converter, and treat the appearance of a
   sanitizer as evidence that the ADR has been reversed.
