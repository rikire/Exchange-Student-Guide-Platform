# Audit of the AI-collaboration layer — 6 September 2026

Phase 0 built this repository's process layer and closed with an audit that read the documents
against the repository. This one reads them against something else: **the platform they run on, and
the published guidance for it.** Both had moved since the layer was designed in early September, and
a rule can be perfectly consistent with its own documents while resting on a mechanism that no
longer works the way it was assumed to.

Method: read `.claude/`, `tools/`, `scripts/` and `docs/ai/` against the current Claude Code
documentation for hooks, skills, memory, permissions and subagents; check each claim in the honesty
table in [README.md](README.md) by trying to break it rather than by rereading it.

What follows is what was found, what was changed, and — at the end — what was considered and
deliberately not done. Several findings were produced by the work itself rather than by the reading;
those are marked, because a defect that surfaces while you are using a thing is better evidence than
one you reasoned your way to.

---

## A-01 — The whole guard layer had a silent off switch *(critical, fixed)*

Every hook in `.claude/settings.json` ran `java -jar tools/target/ai-tools.jar`. That jar is a build
artefact and `target/` is not tracked. On a fresh clone, after `mvnw clean`, or before anyone had run
`scripts/hooks.sh`, it did not exist — and Claude Code treats a hook whose command exits non-zero as
a **non-blocking** error. The session continued with no prompt journal, no protected-path guard, no
bypass refusal and no documentation gate. The only signal was a line on stderr that nobody is
obliged to read, and the honesty table went on claiming that all of it held.

Aggravating: the path was **relative**, so starting a session in `app/` or `docs/` disabled every
hook the same way.

**Verified, not argued.** Moving the jar aside and starting a command reproduced it exactly.

Changed: paths now use `${CLAUDE_PROJECT_DIR}`; a `SessionStart` hook reports a missing or stale jar
before any work begins, written as plain shell precisely so it can run when the jar cannot; and the
honesty table says outright that a mechanism depending on a build has an off switch nobody has to
touch on purpose.

The `SessionStart` reporter is a reporter, not a gate. If `sh` is not on PATH it fails the same
silent way. That is stated where it is documented rather than left for the next audit.

## A-07 — The refusals that mattered most were the ones that disappeared *(fixed)*

`permissions.deny` was unused. The refusals for bypass flags lived only in the jar, so A-01 took them
with it. They now also exist as client-enforced permission rules, which need no build to succeed.

Writing them found a real gap: **`*` does not match the empty string.** A rule shaped
`Bash(./mvnw * -DskipTests *)` missed `./mvnw -DskipTests test`, where the flag follows the program
directly — the most common form. Verified by running exactly that command with the jar hidden and
watching it succeed. Both shapes are now listed.

The rules are scoped to `git` and `./mvnw` rather than matching the flag anywhere, because a rule
that fires on the flag's *name* blocks writing about it — a false positive this repository has
already recorded once. Checked: grepping for the flag, and passing the explicit `=false` form, both
still work.

The two layers are kept together on purpose. The jar's rules parse command segments and understand
`=false`; the permission rules match text. The jar refuses precisely, and the settings layer refuses
at all.

## A-02 — The slash commands were built on the platform's legacy mechanism *(fixed)*

Anthropic's documentation now states that custom commands "have been merged into skills" and keeps
`.claude/commands/` only for backward compatibility. Eleven commands moved to
`.claude/skills/<name>/SKILL.md`. The move was worth making for three specific reasons, not for
currency:

- `/dod` and `/sync-docs` now inject the real output of `git status` and `git diff` into their own
  prompt. Before, they asked the assistant to run a command and report what it saw. This repository
  has twice recorded what that costs — a check reported as passed after it failed, and "BUILD OK"
  printed over a broken compile.
- `/trace-check` and `/course-check` run in their own context. Both read widely and answer briefly.
- Seven commands that write into the record or the human's decision space can no longer be started
  by the assistant at all. A command that files an ADR because it inferred one was wanted is worse
  than no command.

`docs-check` was taught to accept either shape first, so the migration did not need a flag day. It
caught a dangling reference in `definition-of-done.md` on the way.

Deviation from the plan: `/dod` was to run in its own context and does not. Forking returns a
summary, and that checklist's value is twelve separate verdicts; a summary of them is the thing it
exists to prevent.

## A-03 — The rules for writing Java were never loaded while Java was written *(fixed)*

`code-style.md`, `testing.md`, `architecture-rules.md` and `security.md` are about 540 lines that
reached the model only if it chose to open them. The honesty table already conceded that the
test-first rule and the style rules held by good faith — and good faith fails by forgetting, not by
deciding.

Five files in `.claude/rules/` now carry the load-bearing subset with `paths:` patterns, so Claude
Code loads them when a matching file is opened. `docs/ai/` stays canonical; a rule file is a pointer
with an excerpt.

**This introduces a defect no check can catch:** a rule file that contradicts its source. `docs-check`
verifies that the link resolves, not that the excerpt is still faithful. Said plainly in
[README.md](README.md) rather than left to be discovered.

## A-04 — The Definition of Done was graded by whoever wrote the code *(partly fixed)*

The DoD's second reading happened in the context that had just produced the work. `/dod` now hands
the diff to a `dod-reviewer` subagent that receives the change and the criteria without the reasoning
behind either.

Honestly: it is the same model, and it is started by the run it audits. It is an improvement on
self-review, not independence.

The reviewer is told to report nothing when the change is sound. A reviewer asked for findings will
produce them, and chasing invented ones buys defensive code, extra abstraction and tests for cases
that cannot arise.

## A-04b — Nothing showed that any instruction changes behaviour *(partly addressed)*

There are 101 tests over `tools/`. They prove the *tooling* works. **Not one shows that a line in
`docs/ai/` changes what the assistant does.** For a project whose subject is working with an AI, that
was the largest untested surface in it, and it is the same defect the honesty table exists to catch,
one level up: a rule believed to work because it is written down.

`sharpen`, `dod` and `feature` now carry `evals/evals.json` — a realistic prompt and verifiable
statements the answer must satisfy. The number that matters is the difference between the pass rate
with the skill and without it; a skill that changes nothing had instructions that were already
obvious.

**They have been written and not run.** No pass rate is claimed anywhere, and none should be quoted
until the runs exist.

## A-05 — A second record that git could not see *(fixed)*

Claude Code keeps an auto memory: notes it writes to itself between sessions, under
`~/.claude/projects/<repository>/memory/`, loaded into every conversation. It was on, and it held a
note about this project.

The journal's claim is that the record of working with the AI is complete and committed. A store
that only one laptop can see, which the assistant reads and writes and which shapes what it does,
makes that claim false — quietly, which is the part that matters for a viva.

Switched off in `.claude/settings.json`, with the reasoning recorded in
[journal/README.md](journal/README.md), including what switching it back on would cost.

## A-06 — The Stop gate argued from a premise the platform had overtaken *(fixed)*

"Refuse once, so a session cannot deadlock" was reasoned out from first principles. Claude Code stops
honouring a `Stop` hook after eight consecutive blocks, so the deadlock was bounded regardless. The
rule is kept — it is stricter and still right, and eight refusals is seven more than anyone reads —
but the document now says which half is ours.

Noted for later: once application code exists, "the build is green" wants a gate, and the ladder is
prompt → `/goal` condition → `Stop` hook. None is in use, which is correct while there is nothing to
build.

## A-08 — Smaller items

- **`AGENTS.md`** now exists, pointing at `CLAUDE.md` and warning an arriving agent that none of the
  `.claude/` enforcement will run for it.
- **A status line** shows context used and open debt. Context pressure is the constraint the other
  advice follows from; a session that has filled its window forgets instructions rather than
  breaking them.
- **`/doctor`, `/skill-doctor` and `/context`** join the phase-close ritual. `/skill-doctor` is the
  only way to learn that a command nobody's request ever matches has been dead the whole time.

## Found by doing the work, not by reading

Three false positives of the same family surfaced **while making these changes**, all in rules that
cannot tell a use from a mention:

1. The bypass-flag rule refused the commit message describing the bypass-flag fix.
2. The marker rule refused `AGENTS.md`, on its first line about markers. `CommandRules` exempts
   `docs/tech-debt.md`, `docs/ai/` and `.claude/` for exactly this reason and did not know about the
   fourth file whose job is to quote the rules. Fixed, with a test.
3. The marker rule then refused **the test for that fix**. The test now assembles its fixture from
   parts. `CommandRules` already recorded two earlier instances of a rule refusing the file that
   documented it; this is the third and fourth.

This is not a bug to be fixed once. It is the standing cost of a text-matching guard, and the
alternative — a model judging intent — is rejected below. The right response is an exemption list
that is maintained, and a note in the audit each time it grows.

Also noticed: `docs/roadmap/README.md` still lists phase 1 as **not started**, while FR-001 to FR-015,
ADR-0001 and the acceptance criteria were written on 5–6 September. The `SessionStart` hook reports
the phase from that table, so it currently reports something false. Not fixed here — the roadmap is
the other member's to update, and quietly correcting someone's status line is how two people stop
trusting a shared document.

## Considered and not done

**LLM-judgment hooks** (`type: prompt`, `type: agent`) in place of the regex rules that keep
producing the false positives above. Rejected. The guard layer's value is that it is deterministic
and reproducible: the same command gets the same answer every time, and a refusal can be explained at
a viva. A rule that fires *usually* teaches people to retry rather than to fix, and the failure mode
is silent permission. The false positives are the price of a guard that can be reasoned about, and
they are cheap — each one costs a rewording and produces a test.

**`claude -p` running a review in CI.** Rejected: a cost per pull request, an API key in repository
secrets for a two-person course project, and a verdict that is not reproducible between runs. CI's
job here is to give the same answer twice.

**A `PostToolUse` hook running Spotless on the edited file.** Rejected on measurement, having been
planned. A module-wide `spotless:apply` takes **5.5 seconds**, and Spotless offers no reliable
single-file path at the version pinned here. That is 5.5 seconds added to every Java edit, against a
failure that `pre-commit` already catches before it can reach anybody. The original decision to
consolidate checks into `PreToolUse` for latency was right, and this audit's proposal to reverse it
did not survive being timed.

**Packaging `.claude/` and `tools/` as a plugin.** Deferred, not dropped — recorded as `DEBT-002`
with both blockers: the hooks need a jar that `target/` keeps out of git, and every skill links into
`docs/ai/`, which would not exist in the repository it was installed into. A plugin that installs and
then misbehaves is worse than none, for the same reason a slash command that errors is worse than one
that is absent.

---

## What this audit does not establish

- That the evals pass, or that any instruction measurably changes behaviour. They are written and
  unrun.
- That `.claude/rules/` excerpts still match their sources. Nothing checks this.
- That the `SessionStart` reporter will run everywhere. It needs `sh`, and fails silently without it.
- That the guard holds in permissive permission modes. It does not, and
  [README.md](README.md) already said so: a hook answering `ask` is answered automatically there.
  Every fix above that ends in a refusal survives this; every one that ends in a question does not.
