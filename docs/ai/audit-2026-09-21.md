# Audit of the AI process — 21 September 2026

Working record of the process review started on a clean machine with a fresh agent. It holds the
findings, the map of the rules, the contracts of the stages, and the evidence behind each.
Nothing here is a requirement. A proposal is marked as one.

**Authority.** The human agreed in conversation on 21 September: stage 0 before stage 1; a JDK
installed without `sudo`; the branch `process/contract-and-stop`; this file; a baseline eval run;
the scope of stage 1; the wording of rules 2 and 3; the contract-size rule; the change to eval 2.
The details of the process documents were not agreed line by line and are shown as diffs first.

## Method and limits

Read: the instructions, hooks, scripts, CI, `tools/` and the two earlier audits. Run: the
onboarding on this machine, the guard jar on synthetic events, one git probe, a baseline of eight
read-only subagent runs. Official documentation checked for the mechanisms below.

Not established: whether a hook `ask` is answered automatically in permissive permission modes; the
documented output format that makes a `Stop` hook block (the journal of 4 September reports a
refusal observed); hooks in `claude -p` and in the VS Code extension; whether a path rule loads
when a file is created with `Write` and never read. A hook `ask` and a `Stop` block are treated as
working; neither was re-tested.

## Stage contracts

**Stage 0 — environment (done).** Temurin 21.0.12.1+1 in `~/.local/opt`, symlink `java`; SHA-256
matched in three sources. `scripts/hooks.sh` and `scripts/check.sh` passed (135 `tools` tests, 3
`app`); the four "Done when" criteria held; the prompt hook fired in the running session without a
restart. The entry of 14:44 is the tail of the previous turn, written by the Stop hook before the
prompt hook existed in that session: empty prompt, author unresolved. It stays as written.

**Stage 1 — contract and stop (agreed).** Behaviour: read the repository, state a contract, wait for
an explicit confirmation even when the request looks complete, carry it out without asking again,
stop on an observable trigger and recheck what rested on the premise. Files: `CLAUDE.md` rules 2
and 3, `prompting.md`, `stop-and-ask.md`, `.claude/skills/sharpen/SKILL.md` and its evals, and the
copies of rules 2 and 3 in `docs/ai/README.md` and `workflow.md`. Out: a task-state file, the hook
reminder text, `TestFirstRule`, DoD, the guard. Checks: `docs-check`, `check.sh`, the four new evals
before and after. The hook reminder still carries the old exception until stage 1b changes it.

**Stage 1b — hook reminder and journal noise (done).** Commits `c665318` and `16a0814`. The
reminder now states rules 2 and 3. A message the harness relays (`<task-notification>`,
`<agent-message`, `<cross-session-message`) opens no entry and gets no reminder; between turns the
tree is still snapshotted, so the human's earlier edits carry to the next prompt and the agent's own
are not reported as the human's; inside a running turn such a message changes nothing.
`hook subagent` notes a finished subagent. 156 `tools` tests pass, up from 135; each new test failed
on its assertions first, and two deliberate breakages of the snapshot logic are each caught.

The live check found what the scratch probes could not. `SubagentStop` does carry `agent_type` and
`agent_id`: the journal got "Subagent finished: Explore (a0bbecfdd3f5a0ecd)". But a subagent's
report delivered inside a running turn is wrapped in `<agent-message>`, not `<task-notification>`, so
the first filter missed it: the hook overwrote the open entry's prompt and reported the agent's own
edits as "files the human changed by hand", and that entry keeps the hand-back text as its prompt
with the real one only in its English rendering. The entry stays as written; this is its correction.
Starting a machine turn inside a person's turn would also have left that entry unwritten, so it is
now a no-op there. Lesson: a hook's input format is a fact to observe in a real session, and the
synthetic events I wrote encoded only what I already believed.

**Stage 2 — documentation without filler (agreed).** IB-002 becomes a section in `docs-sync.md`;
then one commit per document with a ledger of what was removed. Out: journal, audits, `PLAN-PROMPT`,
`docs/course/`, requirements, ADRs, stakeholder records, generated files.

**Proposals, not agreed.** J: search for skills, plugins and software when a task needs one —
search on its own, install only on an explicit yes, behaviour-shaping tools kept in the project.
K: onboarding fixes N2 to N5 and K1 to K3.

## Eval results — before and after the rules change

Eight read-only subagent runs per state, two per scenario, default model. "Before" ran on the rules
of `9b27227`; "after" on the stage 1 rules, not yet committed at the time. A separate subagent graded
the 16 replies blind: shuffled ids, no knowledge of the state. Expectations:
`.claude/skills/sharpen/evals/evals.json`, ids 4 to 7.

| Scenario | Criteria met | Began implementing | Contract given | Questions to the human |
|---|---|---|---|---|
| S4 complete request | 3/10 → 10/10 | 2/2 → 0/2 | 0/2 → 2/2 | 3 → 5 |
| S5 look up, then ask | 7/8 → 8/8 | 0/2 → 0/2 | 1/2 → 2/2 | 9 → 6 |
| S6 confirmed contract | 8/8 → 8/8 | 2/2 → 2/2 (wanted) | 0/2 → 0/2 (wanted) | 3 → 0 |
| S7 refuted hypothesis | 6/10 → 10/10 | 0/2 → 0/2 | — | 2 → 2 |
| Total | 24/36 → 36/36 | | | |

Each cell reads before → after. S4 is the change: before, both runs began implementing a complete
request ("Спрашивать нечего, начинаю с красного теста"); after, both gave a contract and stopped. S6,
no repeated approval, held. In S7 the earlier replies also stopped and asked for the real event, but
did not separate confirmed, refuted and unknown, and did not name the `HookEvent` change as resting
on the wrong premise. No reply, before or after, asked a question the repository answers (16 of 16).
One before-run reported a wrong measurement (K4); no after-run did.

Cost: 553,688 tokens before and 559,184 after; 727 s and 773 s of subagent time in total.

Limits. Two runs per scenario per state show a direction, not reliability. The rules and the
expectations have one author, and S7 expectation 2 repeats the wording of the recovery protocol, so
S7 measures compliance with the new format more than a better outcome. Subagents do not receive the
prompt hook's reminder, so delivered behaviour is not reproduced, and the reminder still carries the
old exception until stage 1b. S6 and S7 are pasted transcripts. Blinding is imperfect: the lists of
files read betrayed some states. Before-run S7-1 read this session's journal entry, and after-run
S7-2 read this audit. Raw replies stay outside the repository; a rerun gives different texts, and
this table with its quoted evidence is the record.

## Incident notes moved out of documents

Kept here so that a rule document can hold the decision and a link.

- **4 September, `docs/ai/README.md`.** Rule 6 was described as backed by the matrix generator
  before that generator existed; the claim was corrected the same day. A document overstating its
  own enforcement is the defect this layer audits itself for.
- **4 September, the journal rule.** The English-rendering rule had a reminder and a record: the hook
  asked at the start of the turn and wrote `NOT supplied` into the entry at its end. Both fired and
  the rendering still did not appear, so the `Stop` hook now refuses once
  ([journal/README.md](journal/README.md), "The times this was written by hand").
- **Phase 0.** The enforcement table claimed the guard held while a fresh clone had no jar and
  therefore no guard. It was found by auditing the table against the platform rather than against
  itself ([audit-2026-09-06.md](audit-2026-09-06.md), A-01).
- **Early September, `collaboration.md`.** Its upload section presented magic bytes as settling the
  file type. One search showed that polyglots pass and that OWASP says no single technique is
  enough; the section had been confidently incomplete for a week. The rule that a security defence
  is looked up before it is implemented comes from this.
- **3 September, `definition-of-done.md`.** On a throwaway palindrome check an expectation was wrong,
  the run went red, and the expectation was rewritten to match the output. The outcome was correct
  by luck, and the move is the one that makes a suite stop meaning anything; the rule "work out
  which is wrong before changing either" comes from it.
- **4 September, the phase 0 audit** (`roadmap.md`). Phase 0 passed its own readiness criterion with
  a green build and CI, and an audit still found eight divergences, seven of them documents
  describing things that were not there. `docs-check` was written for that class; the audit stays
  because it reads for meaning.
- **7 September, session notes** (`roadmap.md`). Two notes were deleted after their condition was met,
  yet they still held two adopted rules that existed in no permanent document (prefer a glossary term
  to a cross-reference; "not yet approved" and "rejected" are two scenarios). Both were moved into
  `docs/requirements/` first, which is where "check a note before deleting it" comes from.
- **6 September, slash commands.** They moved from `.claude/commands/*.md` to skills: a skill can
  inject the output of a real command into its prompt, can run in its own context, and can be hidden
  from the assistant so that only a person starts it (same audit, A-02).
