**In our own words** — Built the process layer and then spent the end of the week auditing it rather
than extending it. The tooling side: the `ai-tools` jar with the prompt journal, the protected-path
guard, the bash-bypass refusal and the documentation check, plus the git hooks and CI that run them.
The audit on 6 September was the more useful half. It found that every one of those guards runs from
a jar that `target/` keeps out of git, and that Claude Code treats a failing hook as a non-blocking
error — so a fresh clone had been running with the whole guard layer silently off, while the table
claiming what was enforced stayed green. Verified by moving the jar aside and watching the refusals
disappear. Fixed by moving the two refusals that must not depend on a build into the client's own
permission layer, and by adding a session-start report that is deliberately not the jar so that it
can say the jar is missing. Also migrated the eleven slash commands to skills, added path-scoped
rules so the Java and testing rules load when a Java file is opened, and switched off Claude Code's
auto memory because it is machine-local and outside git while the journal claims to be a complete
record.

What this week did not produce is application code. That is the finding of the second audit, also on
6 September: 51 lines of Java in `app/` against roughly 10,000 lines of process, and the schedule
that was set on 2 September has never been checked against it.
