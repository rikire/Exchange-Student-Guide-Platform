# Team

The course prevents freeloading with five layered mechanisms (course requirements, section 10). Four
of them produce artefacts that live here.

| Mechanism | Where it lives |
|---|---|
| Named module ownership | [ownership.md](ownership.md) — generated, never written by hand |
| Git evidence across weeks | The git history itself, summarised in the weekly logs |
| Weekly contribution log | [weekly-log/](weekly-log/) — one file per ISO week |
| Individual viva | [../viva/](../viva/) — questions and answers per slice |
| Peer contribution split | Submitted privately at the final stage, not stored here |

## How we actually work

Both of us take whatever task we like — a feature, a chore, a piece of debt — and finish it under our
own authorship. There are no assigned areas; both of us are responsible for the whole project.

That creates one problem the rubric cares about: it asks for a named owner per module and a rough
balance between us. So ownership is **measured rather than assigned**.
`ai-tools ownership` (phase 2) reads
the git history and reports who has actually done more in each slice.

The point is not bookkeeping. It is that at the final viva each of us has to answer questions about
our own modules and about the other person's. Measured ownership tells us, week by week, which
slices we each need to be able to explain — and if the balance drifts, the next task comes from the
lighter side.

`ownership.md` is generated. Editing it by hand defeats the only reason it is trustworthy.
