# Security, where this code actually touches it

Full document: [docs/ai/security.md](../../docs/ai/security.md).

- **File type is decided by content, not by the client** — Tika reads the magic bytes. But magic
  bytes are necessary and **not sufficient**: a polyglot carries a valid signature and is still
  hostile. Allowlist, never denylist.
- The stored filename is generated by the system; the original lives in a metadata column.
- Media is delivered through a controller, never by mapping a directory to a URL, always with
  `X-Content-Type-Options: nosniff`.
- **Raw HTML passthrough is disabled in the Markdown converter** (ADR-0001), and there is no HTML
  sanitizer: one appearing means raw HTML is being accepted and the ADR has been reversed.
  `th:utext` is only for content the converter produced, with a comment.
- The application never fetches a URL supplied by a visitor. That closes SSRF by not having the code.
- CSRF protection on every state-changing form. Parameterised queries only — concatenation into a
  query is a security defect, not a style question.
- **`N+1` is a security requirement here, not an optimisation.** The number of queries a page issues
  must not grow with the number of rows it shows, and every public list is paginated with a bound
  the client cannot raise.
- No secret in a log line, an exception message or an error page.
